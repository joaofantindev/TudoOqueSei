Closures: funções que lembram de onde nasceram

javascript

javascript

closures.js

2026-10-27

Uma closure nasce quando uma função interna continua acessando o escopo onde foi criada, mesmo depois que a função externa terminou de executar.

O valor não é copiado: a função mantém uma referência viva ao ambiente léxico. Por isso total sobrevive entre as chamadas e cada chamada de criarContador() cria um estado independente.

  • Cada chamada cria um novo escopo.
  • As variáveis ficam privadas, inacessíveis de fora.
  • Módulos e memoização dependem desse comportamento.

Cuidado com o clássico loop usando var: todas as funções acabam apontando para a mesma variável.

function criarContador() {
  let total = 0;

  return function () {
    total += 1;
    return total;
  };
}

const contador = criarContador();
contador(); // 1
contador(); // 2
  • escopo léxico
  • estado privado
  • fábrica de funções

Grid responsivo com uma linha de CSS

css

css

galeria.css

2026-10-25

repeat(auto-fit, minmax(220px, 1fr)) já resolve a maior parte dos grids responsivos: cada coluna tem no mínimo 220px e dividem o espaço restante igualmente, quebrando linhas quando necessário.

A diferença entre auto-fit e auto-fill aparece quando sobram colunas: auto-fit colapsa as vazias e estica as existentes; auto-fill mantém os espaços fantasma.

  • minmax(0, 1fr) evita estouro de conteúdo.
  • gap substitui margins entre itens.
  • min-width: 0 em filhos ajuda com textos longos.
.galeria {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  gap: 16px;
}

.galeria > article {
  min-width: 0;
  padding: 20px;
  border: 1px solid #24241f;
  border-radius: 12px;
}

useEffect sem cleanup é uma armadilha

react

react

nota.jsx

2026-10-23

Todo efeito que cria algo fora do React precisa devolver uma função de limpeza. O cleanup roda antes do próximo efeito e quando o componente é desmontado.

No exemplo, a flag ativo evita atualizar estado depois que o componente sai da tela ou o id muda. Sem isso, uma resposta antiga pode vencer uma requisição mais recente — a clássica race condition.

  • Dependências controlam quando o efeito roda.
  • Requisições podem ser canceladas com AbortController.
  • Timers e listeners sempre precisam de cleanup.
import { useEffect, useState } from "react";

export function Nota({ id }) {
  const [nota, setNota] = useState(null);

  useEffect(() => {
    let ativo = true;

    fetch("/api/notas/" + id)
      .then((res) => res.json())
      .then((dados) => {
        if (ativo) setNota(dados);
      });

    return () => {
      ativo = false;
    };
  }, [id]);

  return nota ? <h1>{nota.titulo}</h1> : null;
}
  • modelo de efeito
  • race condition
  • AbortController

Rebase interativo: limpando o histórico

git

shell

rebase.sh

2026-10-21

git rebase -i abre uma lista de commits para reescrever. Você escolhe o que manter (pick), junta (squash), reescreve a mensagem (reword) ou remove (drop).

O resultado é um histórico linear e fácil de bisectar. A contrapartida: os commits são recriados com novos hashes, então nunca faça rebase de algo que outra pessoa já usa.

  • squash junta commits e pede uma mensagem final.
  • fixup junta sem abrir o editor.
  • Se der errado: git rebase --abort.
git fetch origin
git rebase -i origin/main

# no editor, troque pick por squash
pick   a1b2c3d adiciona card
squash d4e5f6a corrige espaçamento
reword 7890abc ajusta copy

Comprehensions que ainda dá pra ler

python

python

comprehensions.py

2026-10-19

Comprehensions são ótimas quando cabem em uma linha e um pensamento. List, dict e set comprehensions evitam o loop com append e deixam a intenção explícita.

Quando existe mais de um for ou uma condição aninhada demais, volte para o loop normal. Legibilidade ganha da esperteza.

  • Use generators quando não precisa materializar a lista.
  • sum(1 for ...) conta sem criar array intermediário.
  • Dict comprehension exige chave e valor.
pares_ao_quadrado = [n ** 2 for n in range(10) if n % 2 == 0]

titulos_por_id = {nota.id: nota.titulo for nota in notas}

contagem = sum(1 for n in numeros if n > 0)

LEFT JOIN: o que não casa também importa

sql

sql

joins.sql

2026-10-16

INNER JOIN devolve só os pares que existem dos dois lados. LEFT JOIN mantém todas as linhas da esquerda, preenchendo o resto com NULL — inclusive usuários sem nenhuma nota.

Um detalhe que morde: filtros no WHERE sobre a tabela da direita transformam o LEFT JOIN em INNER. Se quer preservar quem não tem correspondência, coloque a condição no ON.

  • COUNT(coluna) ignora NULL; COUNT(*) não.
  • HAVING filtra depois da agregação.
  • Sempre qualifique as colunas no ON.
SELECT u.nome, COUNT(n.id) AS total_notas
FROM usuarios u
LEFT JOIN notas n ON n.usuario_id = u.id
GROUP BY u.id, u.nome
HAVING COUNT(n.id) > 0
ORDER BY total_notas DESC;
  • left join
  • agregação
  • where vs on

Generics: flexibilidade sem perder tipos

typescript

typescript

primeiro.ts

2026-10-12

Generics permitem escrever uma função que funciona para vários tipos sem abrir mão do retorno tipado. O T é um parâmetro de tipo: quem chama decide o valor dele, e o TypeScript infere na maioria dos casos.

Use constraints (T extends { id: string }) quando o corpo precisa acessar propriedades específicas. Sem constraint, o tipo é tão aberto que você não consegue fazer quase nada.

  • Evite any disfarçado de generic.
  • Prefira inferência a tipar tudo na mão.
  • Generics também valem para componentes e hooks.
function primeiro<T>(itens: T[]): T | undefined {
  return itens[0];
}

const nota = primeiro([{ titulo: "closures" }]);
// nota: { titulo: string } | undefined
  • parâmetro de tipo
  • constraints
  • inferência

Persistência local: rascunhos que sobrevivem ao refresh

web

javascript

rascunho.js

2026-10-08

localStorage guarda strings por origem, de forma síncrona e sem prazo de validade. Para objetos, o caminho é JSON.stringify na escrita e JSON.parse na leitura — com tratamento para valores corrompidos.

É útil para preferências e rascunhos pequenos. Nesta página, o conteúdo das notas vive no próprio HTML; o armazenamento local fica reservado para preferências de leitura, como o último filtro usado.

  • Limite de ~5 MB por origem.
  • É síncrono: bloqueia a main thread.
  • sessionStorage morre ao fechar a aba.

Para dados compartilhados, o conteúdo precisa ir para o repositório.

const CHAVE = "learn:rascunho";

export function carregar() {
  try {
    return JSON.parse(localStorage.getItem(CHAVE)) ?? null;
  } catch {
    return null;
  }
}

export function salvar(dados) {
  localStorage.setItem(CHAVE, JSON.stringify(dados));
}
